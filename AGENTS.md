# Правила проекта (Flutter / OpenCode)

## 1. Язык и экономия токенов

- **Только русский язык.** Весь текст, объяснения, вопросы и комментарии в коде — строго на русском. Имена классов, методов, переменных и системные термины — на английском.
- **Никакой «воды».** Без приветствий, извинений, планов действий и прощальных фраз. Сразу код или суть.
- **Минималистичные диффы.** Выводить только изменённые методы, виджеты или строки с контекстом 2–3 строки. Никогда не выводить файлы целиком, если не создаётся новый файл или это не попросили прямо.
- **Краткость.** Пояснения — максимум 2 коротких предложения. Очевидный код не комментировать.

## 2. Запрет на запуск и работа с контекстом

- **Никакого запуска команд.** Запрещены `flutter run`, `flutter test`, `dart analyze`, `build_runner`, `pub get` и любые другие терминальные команды. Только чтение, поиск и редактирование файлов.
- **Точечное чтение.** Не читать файлы >150 строк целиком, не сканировать директории вслепую. Сначала искать нужное через grep, затем читать целевой фрагмент.
- **Игнорировать мусор и кодогенерацию.** Не читать, не искать и не править `*.g.dart`, `*.freezed.dart`, `*.mocks.dart`, `pubspec.lock`, а также папки `.dart_tool/`, `build/`, `android/`, `ios/`, `windows/`, `linux/`, `macos/`, `web/`.
- **Пакетные вызовы.** Группировать операции поиска и чтения в один запрос вместо последовательных шагов.

## 3. Стандарты Flutter и Dart

### Чистый UI и производительность

- Везде, где возможно, использовать `const`-конструкторы против лишних перерисовок.
- Выносить подвиджеты в приватные классы (`class _MyWidget extends StatelessWidget`), а не в методы (`Widget _buildSomething()`).
- Никогда не выполнять тяжёлые вычисления, запросы и инициализацию контроллеров внутри `build`.
- Для длинных списков использовать только ленивые конструкторы (`ListView.builder`, `SliverList`).

### Надёжный Dart

- Строгая типизация: `dynamic` запрещён без крайней необходимости (например, парсинг сырого JSON).
- Избегать оператора `!` (null-assertion). Использовать `?.`, `??` или паттерн-матчинг.
- Всегда освобождать ресурсы (`TextEditingController`, `ScrollController`, `AnimationController`, `StreamSubscription`) в `dispose()`.
- `final` для всех локальных переменных, которые не перезаписываются.

### Форматирование

- Стрелочные функции (`=>`) для однострочных методов и геттеров.
- Висячие запятые (trailing commas) в многострочных параметрах и виджетах для чистых и компактных диффов.
